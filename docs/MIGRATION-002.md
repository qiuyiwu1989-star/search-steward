## 推荐目标

## 切换步骤

1. 维护窗口确认两个任务都没有发送中任务；备份私有队列、成功历史、管家 SQLite 和原服务配置到非网页目录，记录校验和及权限。
2. 从已成功记录和待提交记录生成迁移清单，与正式公开清单对照。明确 URL 版本；历史成功项不能因新数据库为空就再发。没有证据的“可能成功”进入待核实。逐项迁移函数和自动验收尚待实现，禁止直接用 enqueue 批量导入历史记录。
3. 暂停 Codex 发送，并确认旧服务当日实际额度；原服务调整执行新队列脚本，仍只有一个 timer。凭据存环境/私有配置，按主机分别授权。
4. 默认 HTTPS。若百度 HTTPS 证书仍不可验证，不关闭验证；是否使用官方 HTTP 接口是单独的部署决定。执行器提供显式 --allow-http，默认不用。
5. 新执行器先 dry-run：核对已成功不再待提交、跨域 URL 被拒绝、失败/未知不会丢失。
6. 在有额度时只提交一条；保存真实回执，幂等导入现有管家。回执成功后再启用每日预算，额度不足正常等待。
7. Codex 改为监控唯一服务的状态、待提交数、异常和首次清空，不能再次调用发送脚本。

## 回滚

停止新执行器；保留新队列及回执，恢复旧服务配置，但不自动恢复旧队列发送。先把切换期间新增成功项合并，确认无重复后才恢复发送。失败回执、unknown 状态和原数据库不删除。
