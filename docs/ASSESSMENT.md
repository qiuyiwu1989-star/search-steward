# SEO 管家接手评估 · 2026-10-27

## 已核实的系统

公开仓库提取自个人网站生产模块的代码快照，随后增加独立运行适配；不复制宿主完整仓库、历史、数据库和配置。

在用模块包含：站点总览、公开巡检、公开清单覆盖、整改与复验、提交回执、多平台核验、GEO 观测和效果历史。后端为 Flask Blueprint + SQLite；前端为 HTML/CSS/JS。已有地址范围控制、公网 IP 校验、TLS 校验、断点续扫、凭据过滤与回执幂等。

检查时点的生产聚合数：24 个站点、40 次巡检、194 项任务（129 待处理、1 进行中、64 完成）、19 条记录。它们是时点统计，不是全站质量评分，也不是所有页面已检查。开源仓库不附带生产业务记录。

生产存在小时巡检、百度和 IndexNow systemd timer；本聊天另有 Codex 触发的百度队列执行器。不能因当前用户 crontab 没有任务就判断无调度。不同提交执行器尚未证明共用幂等状态，这是优先核查项；不得新增第三个执行器或盲目删除现有队列。

## 当前能力边界

1. 管家能发现技术问题并记录整改，尚不能把原始内容持续生成高质量公开页面。
2. 个人站覆盖器直接了解书籍、演讲、文章、方法论等 JSON 和目录，是站点适配器，不是通用内容模型。
3. 原模块依赖宿主登录与前端壳；新仓库独立入口使用访问令牌，数据 API 默认拒绝匿名访问。
4. 提交管理主要是登记与旁路回执，不是主动提交任务编排器。
5. GEO 是人工/导入观测，平台登记不代表完成平台连接。
6. 页面文本含导航，字符少只是线索；未实现正文抽取、语义质量判定、真正 CWV 测量。
7. 展示窗口有限，不等于数据库全量；当前没有完整备份/恢复和版本化迁移工具。
8. 新通用覆盖器主动把地图、目录覆盖标为未知；保留个人站适配器，后续需用统一插件契约恢复对应能力。

## 系统定位

优先服务自身个人站与企业站的持续改进，输出可执行的页面任务和核验依据。独立仓库先承载通用巡检与管理核心，不把全站内容管线搬进来。

分层：内容资产与来源 → 站点适配器 → 页面规划/生成 → 发布闸门 → 巡检/整改 → 提交执行与回执 → 搜索/引用/咨询反馈。

知识原子与公开网页不是一一对应：一个方法或完整问题可以成页；孤立金句通常不能自动独立成页。源码开源不意味着发布内部内容或开放管理 API。
