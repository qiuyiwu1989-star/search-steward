# SEO / GEO 管家提升任务

以下是建议任务，不表示已实现。以自有个人站、造物云站两个真实适配器验收，不预先扩展成多租户 SaaS。

| 编号 | 优先级 | 任务及交付 | 验收标准 |
|---|---|---|---|
| S01 | P0 | 统一执行器和提交状态 | 清点 systemd、Codex、发布工作流；明确唯一提交负责人；同域同 URL 同版本不重复执行；无回执不标成功；失败和额度不足保留；实际回执进入管家 |
| S02 | P0 | 权威公开清单及站点适配器 | sites/content schema 版本化；接入个人站和造物云；页面标记用途、正式 URL、发布状态；草稿及未授权案例不进入公开清单；旧入口仍独立核验 |
| S03 | P0 | 按影响分级与问题合并 | 区分抓取失败、规范冲突、内容缺口、体验提醒；合并同源模板问题；网络偶发不等同永久故障；优先队列展示受影响公开页面数和证据 |
| S04 | P0 | 发布前闸门与上线后验证 | 检查空产物、私有来源、noindex 冲突、失效 canonical、JSON-LD 解析；严重错误阻断；部署后记录版本、网址和内容摘要；不会将旧问题自动假关闭 |
| S05 | P1 | 内容身份、出处与版本 | 为方法、章节、案例、方案定义稳定 ID、作者、来源、修订、公开授权；可追溯原文；AI 解释与作者原话分开；数据和履历带来源及有效时间 |
| S06 | P1 | 页面规划与拆分建议 | 一个问题/完整方法对应独立页；发现薄页、近似重复、孤立页；输出合并/保留/新建建议和依据；不按原子数自动造页、不擅自修改正文 |
| S07 | P1 | 页面生成模板与预览 | 先支持主题、方法论、案例、章节、企业方案；HTML 原始正文可读；按页生成标题摘要/canonical/合理 schema；公式含定义算例边界；人工预览确认再发布 |
| S08 | P1 | 有语义的内链与跨站路径 | 用解释/应用/支持/修订关系生成导航；从个人站观点连到企业方案并能回到来源；不按关键词盲连；完整记录建议和最终采用链接 |
| S09 | P1 | 搜索效果真实导入 | 先支持百度/GSC/Bing 文件导入，再按授权接 API；保存站点、查询、页面、区间、来源和去重键；未知不填零，不把索引快照跨期相加 |
| S10 | P1 | GEO 基准集及准确性审校 | 加入非品牌问题、品牌核验、方法归属三类；区分产品/API、模型、日期、联网模式；保存引用和无引用；复测可比较，不声称所有用户都得到同一回答 |
| S11 | P2 | 阅读与有效咨询反馈 | 两站统一事件口径；记录章节继续阅读、工具使用、合作入口及经确认有效咨询；区分入口点击和实际商机；不上传个人信息到公开仓库 |
| S12 | P1 | 运行可靠性 | SQLite backup/restore、迁移版本、超时任务恢复、重试退避、审计保留策略；恢复测试通过；敏感目录不暴露；队列监控和异常通知 |

## 推荐实施顺序

1. S01—S04：先统一事实、执行与发布边界，减少待办噪音和重复提交。
2. S05—S08：以企业 AI 转型主题做闭环，接入一组章节、两个方法、一个授权实践和一个造物云方案；不要先批量改全部书籍。
3. S09—S12：用真实搜索、引用及咨询反馈安排下一批优化，完善恢复和运行能力。

## 第一批内容试点验收

- 新内容可自动进入公开清单、生成入口和地图，数据库记录版本。
- 一个严重问题能从发布阻断到整改、复验形成完整证据链。
- 同一新 URL 在唯一提交器排队，成功回执进入同一站点。
- 页面独立回答一个问题，原文、公式、授权和引用关系可追溯。
- 从观点进入方案/咨询的路径可观察；未取得效果数据时明确留空。
